## Changes vs 0.4.0 (vector25 medians)

* **6x2 NN/TN micro-kernel:** 512x384x384 is 1.23x faster (82 to 84 GFLOP/s single-threaded), 128x768x384 1.18x,
  32x768x384 1.16x, TN 384x768x32 1.19x, 7x385x383 1.45x. 1-row GEMVs use the same code as before (within
  noise; 1x192x384 measured 0.94x, which is 0.4 us). Bits are unchanged: `tools/bitcheck` gives the same hash
  for 0.4.0 from Maven Central and this branch.
* **2-D tiled `ParallelF32`:** a vocabulary-sized GEMV 1x16384x384 now parallelises by columns (4.1–4.5x;
  0.4.0 could not split it at all). Products below `minWork` (4M multiply-adds) stay on the calling thread, so
  small GEMVs no longer get about 4x slower from the 60–90 us pool hand-off. Large products are 1.05–1.2x faster
  than 0.4.0, mostly thanks to the new micro-kernel. Scaling still flattens after 6–12 workers; the fixed
  dispatch cost and memory bandwidth limit it. One 1x16384x384 single-worker fork was faster than the other
  two (1.8 vs 2.4–2.5 ms).
